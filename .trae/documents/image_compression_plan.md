# 图片压缩功能实现计划

## 一、需求分析

### 1.1 业务背景

商家后台系统在添加菜品时需要上传菜品图片，手机拍摄的图片通常较大（几MB甚至几十MB），导致：

* 小程序端加载图片消耗大量流量

* 图片加载速度慢，影响用户体验

### 1.2 解决方案

使用 Tinify API（TinyPNG/TinyJPG）对上传的图片进行压缩处理，压缩后再上传到服务器。

### 1.3 功能需求

| 需求点  | 描述                           |
| :--- | :--------------------------- |
| 图片压缩 | 上传图片前先调用 Tinify API 进行压缩     |
| 进度展示 | 压缩过程中显示进度条，提示用户等待            |
| 成功提示 | 压缩成功后提示用户压缩结果（如压缩率）          |
| 失败降级 | API 调用失败时，提示用户并需要用户确认后才能上传原图 |
| 错误处理 | 处理网络超时、API 限额等异常情况           |

## 三、API 接口设计

### 3.1 后端接口

#### POST /upload/compress

**功能**: 接收图片并返回压缩后的图片

**请求体**:

```
Content-Type: multipart/form-data
Body: file (图片文件)
```

**成功响应** (HTTP 200):

```json
{
  "success": true,
  "data": {
    "url": "/uploads/compressed-xxx.jpg",
    "originalSize": 2048000,
    "compressedSize": 512000,
    "compressionRatio": 75
  }
}
```

**失败响应** (HTTP 200):

```json
{
  "success": false,
  "message": "Tinify API 调用失败：API 密钥无效",
  "allowOriginalUpload": true
}
```

### 3.2 前端调用流程

```
1. 用户选择图片 → 触发 handleFileChange
2. 显示压缩进度条，设置 compressing = true
3. 调用 /upload/compress 接口
4. 压缩成功 → 显示成功提示，继续上传到服务器
5. 压缩失败 → 显示失败提示，弹出确认框
6. 用户确认 → 上传原图到 /upload/image
7. 用户取消 → 取消上传
```

## 四、进度条设计

### 4.1 进度展示位置

在图片预览区域显示压缩进度，替换原有的"上传中..."文字。

### 4.2 进度条样式

* 线性进度条，显示百分比

* 压缩成功后显示绿色对勾和压缩率

* 压缩失败后显示红色警告图标

### 4.3 状态流转

```
[选择图片] → [压缩中 0-100%] → [压缩成功/失败]
                                     ↓
                          [上传到服务器] / [用户确认上传原图]
```

***

## 五、代码安全性

### 5.1 API 密钥保护

* 密钥存储在后端环境变量中，前端不直接访问

* 后端通过 HTTP Basic Auth 调用 Tinify API

### 5.2 文件类型验证

* 后端验证上传文件必须是图片格式（JPG/JPEG/PNG/GIF/WEBP）

* 限制文件大小（最大 5MB）

### 5.3 错误处理

* 捕获 Tinify API 各种错误码：

  * 401: 认证失败（密钥无效）

  * 402: API 调用次数超限

  * 415: 不支持的图片格式

  * 5xx: 服务端错误

***

## 六、性能考虑

### 6.1 压缩超时处理

* 设置合理的超时时间（30秒）

* 超时后自动降级为原图上传

### 6.2 进度反馈

* 使用流式进度更新（如果 Tinify API 支持）

* 显示预估剩余时间

### 6.3 并发限制

* 同一时间只允许压缩一张图片

* 避免过多并发请求导致服务器压力

## 八、风险评估

| 风险       | 描述                   | 影响           | 应对措施                   |
| :------- | :------------------- | :----------- | :--------------------- |
| API 调用限额 | Tinify 免费版每月 500 次压缩 | 超过限额后压缩功能不可用 | 在后台管理中显示剩余压缩次数，超限时自动降级 |
| API 密钥泄露 | 密钥被恶意获取              | 可能产生费用或服务被滥用 | 密钥存储在环境变量中，定期轮换        |
| 压缩耗时过长   | 大图片压缩可能耗时超过 30 秒     | 用户体验下降       | 设置超时时间，超时自动降级          |
| 压缩质量问题   | 压缩后图片质量不可接受          | 影响菜品展示效果     | 提供压缩质量选项（高质量/标准/低质量）   |
